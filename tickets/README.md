## How to Use These Tickets

1. Open a ticket file (e.g., `02-domain-restructure.md`)
2. Follow the **Task Description** and **Implementation Steps**
3. Before marking VERIFIED, ensure **ALL Validation Conditions** pass
4. Provide **Proof of Verification** in the ticket
5. Update status: `Status: VERIFIED ✅`

## Verification Process

Each ticket includes:
- **What** needs to be built
- **Why** it matters (architectural impact)
- **Acceptance Criteria** (must-haves)
- **Validation Conditions** (prove it works)
- **Proof Required** (tests, logs, file existence, behavior checks)

No ticket can be marked VERIFIED without explicit proof.
